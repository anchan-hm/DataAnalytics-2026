# Ex2.A Exploring the Northwind Database



1. Categories
* Represents: CategoryID represents Product categories
* Primary Key: Yes, CategoryID
* Foreign Key: No
* Valuable for Power BI?: Yes, it connects Categories to Products
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Counting categories and grouping them by category



2\. Customers

* Represents: CustomerID represents each customer in the company's database
* Primary Key: Yes, CustomerID
* Foreign Key: No
* Valuable for Power BI?: Yes, it connects Customers to Orders
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Text
* Calculations?: Orders per customer and revenues generated by customers



3\. Employees

* Represents: EmployeeID represents each employee for company's database
* Primary Key: Yes, EmployeeID
* Foreign Key: No
* Valuable for Power BI?: Yes, it connects Employees to Orders
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Orders handled by each employee and calculating employee productivity



4\. EmployeeTerritories

* Represents: EmployeeID represents each employee for each territory
* Primary Key: Yes, EmployeeID and TerritoryID
* Foreign Key: Yes, EmployeeID comes from Employees table and TerritoryID comes from Territories table
* Valuable for Power BI?: Yes, it connects Employees to Territories 
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of territories per employee, employees per region



5\. OrderDetails

* Represents: OrderID represents each order item in an order
* Primary Key: Yes, OrderID and ProductID
* Foreign Key: Yes, OrderID comes from Orders table and ProductID comes from Products table
* Valuable for Power BI?: Yes, it connects Orders to Products
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Revenue, amount sold, discounts, total sales



6\. Orders

* Represents: OrderID represents each order made by customers
* Primary Key: Yes, OrderID
* Foreign Key: Yes, CustomerID comes from Customers table
* Valuable for Power BI?: Yes, it connects Customers, Employees and OrderDetails
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of orders, order information, shipping information, total orders per customer



7\. Products

* Represents: ProductID represents each product from company
* Primary Key: Yes, ProductID
* Foreign Key: Yes, CategoryID comes from Categories table
* Valuable for Power BI?: Yes, it connects Products to OrderDetails
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Total sales per product, units sold, product performance



8\. Region

* Represents: RegionID represents grouped territories
* Primary Key: Yes, RegionID
* Foreign Key: No
* Valuable for Power BI?: Yes, it supports categorizing territories
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of territories per region, region performance



9\. Shippers

* Represents: ShipperID represents shipping company per order
* Primary Key: Yes, ShipperID
* Foreign Key: No
* Valuable for Power BI?: Yes, it connects Shippers to Orders
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of orders per shipper and shipping performance



10\. Suppliers

* Represents: SupplierID represents each company per product
* Primary Key: Yes, SupplierID
* Foreign Key: No
* Valuable for Power BI?: Yes, it connects Suppliers to Products
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of products per supplier and supplier performance



11\. Territories

* Represents: TerritoryID represents each territory per region
* Primary Key: Yes, TerritoryID
* Foreign Key: Yes, RegionID comes from Region table
* Valuable for Power BI?: Yes, it connects Region to EmployeeTerritories
* Appropriately named?: Yes
* If not, what's a more appropriate name?: N/A
* Data type?: Whole numbers
* Calculations?: Number of employees per territory, territory performance and territory counts per region
